# protomap-dl — воркер скачивания

Забирает задачи из Firestore, качает медиа по ссылке через `yt-dlp` и отправляет
файл в Telegram напрямую.

## Зачем отдельная машина

YouTube и TikTok жёстко режут запросы с дата-центровых IP, и адреса Google Cloud
среди них самые заблокированные — из Cloud Functions это работать не будет
(«Sign in to confirm you're not a bot» на каждой второй ссылке). С обычного
провайдерского канала те же ссылки качаются без вопросов.

Входящие подключения не нужны: воркер сам опрашивает Firestore и сам ходит
в Telegram. Проброс портов и белый IP не требуются.

## Как это устроено

```
Telegram ─► бот (Cloud Function) ─► задача в Firestore (tg_download_queue)
                                              │
                                    воркер забирает транзакцией
                                              │
                              yt-dlp ─► файл ─► Telegram Bot API
```

Файл не проходит через Firebase: иначе он считался бы исходящим трафиком
Cloud Functions, а бесплатных 5 ГБ в месяц на видео хватает примерно ни на что.

## Развёртывание

Проверялось на Fedora CoreOS с Docker 29.7.2.

### 1. Каталоги на хосте

```bash
sudo mkdir -p /mnt/storage/data/protomap-dl/{work,bin,secrets}
sudo chown -R 10001:10001 /mnt/storage/data/protomap-dl
```

UID 10001 — тот же, под которым бежит контейнер. Если владельца не поменять,
`Permission denied` вылезет **не при старте, а на первой же ссылке**.

Временные файлы намеренно лежат на 2 ТБ HDD, а не на SSD: видео пишутся
и удаляются постоянно, за год это заметный износ.

### 2. Ключ сервисного аккаунта

Положить JSON-ключ Firebase в
`/mnt/storage/data/protomap-dl/secrets/sa.json` и закрыть права:

```bash
sudo chmod 600 /mnt/storage/data/protomap-dl/secrets/sa.json
sudo chown 10001:10001 /mnt/storage/data/protomap-dl/secrets/sa.json
```

### 3. Настройки

```bash
cp .env.example .env
# заполнить TELEGRAM_BOT_TOKEN
```

### 4. Запуск

```bash
docker compose up -d --build
docker compose logs -f
```

В логах при успешном старте:

```
[worker] Запуск, id=...
[ytdlp] Обновлён, версия 2026.xx.xx
[worker] yt-dlp 2026.xx.xx, параллельно задач: 2
```

## Проверка

В чате, где включена возможность `download`, отправить ссылку на YouTube Shorts
или TikTok — бот должен ответить видео.

Команда `/dlstatus` в чате показывает, жив ли воркер, версию `yt-dlp`, длину
очереди и последнюю ошибку.

## Обслуживание

**`yt-dlp` ломается часто** — YouTube меняет отдачу, релизы выходят чуть ли не
еженедельно. Контейнер при каждом старте скачивает свежий бинарник в том
`bin/`, поэтому достаточно раз в неделю перезапускать:

```bash
docker compose restart
```

Можно повесить на systemd-таймер. Без этого через месяц скачивание встанет,
и выглядеть это будет как «ничего не качается», без внятной ошибки.

**Логи** ограничены 3 файлами по 10 МБ (`logging` в compose), чистить не нужно.

## Особенности этой машины

**SELinux в enforcing.** Суффикс `:z` стоит на каждом bind-mount в
`docker-compose.yml`. Если начнёт ругаться на доступ к файлам — проверять
именно его, а **не** отключать SELinux через `label=disable`: это контейнер,
который скармливает `yt-dlp` произвольные URL из публичного чата, и изоляция
тут нужна ровно поэтому.

**Автообновления CoreOS с перезагрузкой.** `restart: unless-stopped` плюс
автозапуск демона Docker переживают их сами, отдельный systemd-юнит не нужен.

## Защита

Модель угрозы тут не «кто-то из своих подложит гадость», а **компрометация самого
сервиса**: это безголовый сервер, скармливающий `yt-dlp` произвольные URL из
чата, и на машине лежат ключ Firebase Admin и токен бота. Отсюда всё ниже.

### Что уже сделано в коде

**Ссылка проверяется в воркере, а не только в боте** (`src/urlcheck.ts`).
Дублирование намеренное: задачу ставит бот, но запрос из домашней сети делает
воркер, и решать, куда идти, должен тот, кто идёт. Отклоняются:

- всё, кроме `http`/`https` — иначе остаются `file://` и прочее;
- частные диапазоны (`10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`),
  `localhost`, `.local`, `.internal`;
- ссылки по IP-литералу — белый список ведётся по именам, обращение по адресу
  означает попытку его обойти;
- хосты вне списка разрешённых.

Без этой проверки достаточно прислать в чат `http://192.168.1.1/...`, чтобы бот
сходил на роутер из домашней сети и принёс ответ в Telegram. Отдельно проверено,
что закрыт `169.254.169.254` — эндпоинт метаданных, классическая цель.

**`yt-dlp` запускается с подчищенным окружением.** Ему передаются только `PATH`,
`HOME` и `TMPDIR`. Это большая программа, разбирающая недоверенный ввод, — то
есть ровно тот код, который ломают. Наследование `process.env` отдало бы при
удачном эксплойте и токен бота, и путь к ключу Firebase.

**Бинарник `yt-dlp` проверяется по SHA-256** при обновлении. Мы скачиваем
исполняемый файл и запускаем его от своего пользователя; проверка закрывает
подмену по дороге. Не совпало — обновление отменяется, работаем на прежней
версии.

**Контейнер заперт:** непривилегированный пользователь, корневая ФС только на
чтение, все capabilities сброшены, `no-new-privileges`, лимиты по памяти,
процессорам и числу процессов.

### Что стоит сделать на хосте

**Закрыть контейнеру доступ в локальную сеть.** Проверка в коде уже это делает,
но firewall — второй рубеж на случай ошибки в ней:

```bash
# подставить реальную подсеть docker-сети контейнера
sudo iptables -I DOCKER-USER -s 172.17.0.0/16 -d 192.168.0.0/16 -j DROP
sudo iptables -I DOCKER-USER -s 172.17.0.0/16 -d 10.0.0.0/8 -j DROP
```

**Права на ключ:** `chmod 600`, владелец `10001`.

**Не отключать SELinux** через `label=disable`, когда что-то не открывается.
Правильный путь — суффикс `:z` на монтировании.

### Если что-то случилось

Отозвать ключ сервисного аккаунта в консоли Firebase и перевыпустить токен бота
у BotFather. Оба меняются без правки кода: ключ — заменой файла, токен — строкой
в `.env`.

## Что внутри контейнера

- Debian (`node:22-slim`), **не** Alpine: официальный бинарник `yt-dlp` собран
  под glibc и на musl не запускается.
- `ffmpeg` — обязателен. YouTube отдаёт видео и звук раздельными потоками, без
  него получится ролик без звука. Это ремукс, не пережатие: процессор не грузит.
- Непривилегированный пользователь, корневая ФС только на чтение, все
  capabilities сброшены, лимит 2 ГБ памяти.

## Ограничения

- **50 МБ** — потолок загрузки файла ботом, лимит Bot API. Не обходится ничем,
  кроме собственного сервера Bot API. Видео больше лимита не перекодируется:
  на i7 шестого поколения без видеокарты это заняло бы минуты, поэтому бот
  честно отвечает, что файл слишком большой.
- Одна ссылка на сообщение. Плейлисты не разворачиваются (`--no-playlist`).
- `e621` качается отдельным путём через их JSON API — `yt-dlp` такой сайт
  не знает.
